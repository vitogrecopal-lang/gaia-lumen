# Dynamic public updates and reader-led verification

The Terra e spazio dashboard now includes two recent headline cards per topic (space, climate, international relations), using the existing shared /api/world-dashboard request. No new AI calls, credentials or browser notification permissions are required. Refresh remains every five minutes when visible and enabled, with five-minute server caching. A first snapshot does not trigger new-item notices; following snapshots compare article URLs. Counts describe received bulletins, not hazards or independently corroborated events.

NOAA/NCEI climate monthly reports are the sixth source, using the official feed linked from https://www.noaa.gov/rss-feeds : https://www.ncei.noaa.gov/access/monitoring/monthly-report/rss.xml . Climate.gov is archived and is not used. Publication dates and reception timestamps remain separate; monthly reports must not be described as real-time climate observations. Source failures retain last known data with stale status; complete fetch failure marks cards and verification details as not updated.

The critical-reading module follows the verification/comparison principles requested by the user for Katerina (a narrative reference, not a scientific validator). Readers select an original bulletin, optionally compare another, record four self-reported steps and notes, and export a local TXT. No truth score, automatic corroboration or AI summary is generated. Two bulletins are not assumed to be independent. Notes are memory-only and reset when changing the primary bulletin; they are not posted to the server or stored in localStorage. Download to retain them. Cards and critical-reading selectors use the whole received sample; filters below the cards apply to map and timeline.

Verification: npm run check; npm run smoke; node scripts/world-feed-test.mjs; node scripts/world-updates-test.mjs. Check the rendered mobile layout and complete selection/comparison/export flow before release. No payment or chat behavior was changed.
